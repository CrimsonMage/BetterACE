# bace-transport

Implemented a pure bounded `Peer` driver and paired nonblocking `UdpEndpoints` adapter. The runtime owns their dedicated network thread, lifecycle, admission and bounded channel composition. No networking API mutates world state or obtains a clock implicitly.

`Peer::new(config, seeds, monotonic_ms)` begins **after** the handshake. The session adapter supplies client/server identities and cryptographic seeds. Incoming packet sequence starts after 1, incoming message sequence starts at 1, outgoing message sequence starts at 0, and encrypted server packets start at 2. `receive` returns ordered complete `ReceivedMessage` values, retaining queue and fragment identity, plus non-gameplay control observations. `poll(monotonic_ms, portal_year_seconds)` emits a bounded batch of datagrams. Call `enable_time_sync` when the connect response is accepted. Handshakes, authentication, endpoint binding and timeouts remain adapter responsibilities.

Implemented transport behaviors:

- Checksum verification, bounded packet ordering, independently ordered message completion and 448-byte fragmentation/reassembly.
- Queue-aware outgoing bundling, tail packing, UI queue ordering, five-millisecond bundle spacing and bounded output batches.
- Two-second ACK scheduling, twenty-second time synchronization, echo responses, bounded NAK requests, retransmit rejection, 120-second packet-cache retention and exclusive ACK cleanup. ACK-only and NAK packets do not consume a packet sequence; retransmissions preserve the original ISAAC contribution.
- Explicit budgets for partial/completed messages, outgoing messages, packet ordering, cached packets and reply queues. Outbound message size has its own `PeerConfig::max_outgoing_message_bytes` cap, separate from incoming reassembly. An outbound message may span more packets than the retransmit cache can hold at once: emission pauses until ACKs free cache space, while ACK-only controls continue. Reliable state/queue failure closes `Peer`; callers must release the corresponding session and must not retry output on that closed peer.
- `Peer::can_enqueue_batch` checks a complete reliable batch without changing the peer. It returns false for temporary outgoing pressure, while invalid messages and batches too large to ever fit return errors. The adapter can retain a temporarily blocked batch and retry after poll drains buffered fragments.
- Paired base/base+1 sockets, atomic bind failure, reusable 1025-byte receive buffers to detect the 1024-byte inbound limit, 484-byte outbound limit, and nonblocking send backpressure. Initial replies use the client-facing socket; established server output uses the companion socket and the session-validated destination.

On receive, wrong-peer identity, malformed wire data and invalid checksums return errors without refreshing any session deadline. The adapter must inspect `is_closed()` to distinguish a terminal reliable-state failure. Only successful input may refresh authenticated activity. On output, `WouldBlock` requires retaining the exact datagram in a bounded adapter queue; successful `poll` output cannot be discarded. Cache and message expiration use explicit monotonic milliseconds, independent of the wrapping packet-header time.

## Provenance and validation

Official source: [NetworkSession.cs](https://github.com/ACEmulator/ACE/blob/47edade3bd3f6044b676d4eb877c4965c7eda62b/Source/ACE.Server/Network/NetworkSession.cs), `MessageFragment.cs`, `ClientPacket.cs`, `MessageBuffer.cs`, `SessionConnectionData.cs`, and `GameMessageGroup.cs`, at the same ACE pin. Retained upstream provenance and AGPL-3.0-only licensing apply.

`bace-compat` has compiled official C# oracle vectors for exact packet/retransmit bytes and primitives. Its `transport.json` fixture executes eight verbatim extracted `NetworkSession` methods together with unmodified `NetworkBundle`, `MessageFragment`, packet serializers and ISAAC. Inputs are synthetic; dependencies supply clocks, logging and byte capture. Every upstream file is compared with immutable GitHub bytes and whole-file/extracted-method SHA-256 values are recorded. `transport_vectors.rs` compares queue 3/9 interleaving, tails, optional-header budgets, ACK/NAK, retained-cache boundaries and ISAAC retransmission bytes. Regenerate with `python3 tools/bace-compat/oracle/transport_generate.py --source .reference/ACE-47edade3bd3f6044b676d4eb877c4965c7eda62b --dotnet /path/to/dotnet`. `tests/peer.rs` exercises controlled-clock peer transcripts, reordering, missing messages, retransmit/cache behavior, clock wrapping, limits, checksum recovery and echo/CICMD behavior. `tests/bundling.rs` checks packing boundaries and UI behavior. The independent bundle goldens establish parity for the enumerated valid packing scenarios; they do not establish full session-loop parity. `tests/udp.rs` exercises both local sockets, oversized input and atomic bind failure on the platform where the tests run. Linux validation does not establish Windows/macOS or stock-client compatibility.

The supplied divergence register's rows 48/49 describe a different ACE shard and retail/client observations; they do not replace the official pin. Unsequenced CICMD `{1, 0}` is accepted as an inert session observation and creates no response. A drifting finite EchoRequest is echoed without adjudicating a speedhack from untrusted client clocks. AccountBooted/referral wire and lifecycle policy (rows 52/53) belong to wire/session.

## Intentional hardening and remaining limits

- Finite budgets, exact fragment consistency, explicit sequence exhaustion/reconnect, maximum incoming packet gap 256, and terminal expired-message/retransmission-unavailable failures replace unbounded or irrecoverable state. Default reassembly budgets are 64 partial and 64 completed messages, 256 KiB/message, 1 MiB each of partial/completed payload, and 30-second lifetimes. These are engineering budgets pending production evidence.
- Checksum verification uses a candidate key stream. Invalid unauthenticated packets cannot consume the peer's future key-search window. Valid incoming checksums retain ACE's key behavior.
- Queue selection rotates to avoid indefinite starvation; optional ACK/sync/echo controls use their own packets. These scheduling choices are not claimed byte-for-byte equivalent to ACE's entire session loop. A gap requests bounded NAKs on polling, including a single missing packet; ACE triggers requests on sufficiently later incoming packets.
- Tail fit uses the actual final fragment size. ACE's modulo-based `TailSize` underestimates exact-multiple tails: the compiled oracle emits a 504-byte datagram for messages of lengths `[4, 896]`. The bounded implementation emits three datagrams of at most 484 bytes and preserves both messages. This explicit deviation has an independent regression.
- Large reliable messages use an ACK-paced retransmit cache instead of exceeding its fixed packet budget. Sync/echo controls wait for cache room; ACK-only packets still flow. The largest configured outbound message cannot exceed 65,535 fragments of 448 bytes or the configured outbound queue budget. This is a bounded scheduling choice, not a claim of a stock-client DAT transfer transcript.
- Client time/flow/command observations are not authoritative physics input. Nonfinite timestamps fail explicitly; finite clock drift alone never logs off a player. This is an intentional authority difference from ACE's `VerifyEcho` enforcement.

Deferred acceptance: full compiled official scheduler trace replay, real stock-client session transcripts, measured production budgets, and Windows/macOS execution. This crate's tests establish the bounded transport foundation, not complete network/gameplay parity.
