# bace-fellowship

BetterACE's bounded fellowship membership and shared-reward rules. The simulation
owns a single indexed fellowship registry consumed by network actions, native NPC
emotes, fellowship spells and reward preparation. Members retain source order;
maximum membership is nine. Lifecycle rules include leader/open recruitment,
locked departed-member rejoin, leader transfer and ordered recipient projections.

`rewards` follows pinned official ACE `Entity/Fellowship.cs` sharing eligibility,
even/proportional XP, quest flat splits and distance scalars. The original earner
retains the original reward kind; other recipients use Fellowship, which matters
for item XP and messages. Luminance's pure helper preserves quest non-sharing and
division by all members before range eligibility. A helper alone is not evidence
that every live reward origin is connected.

`tests/reward_oracle.rs` consumes 92 vectors generated by executing the original pinned
C# methods with `oracle/ace_rewards.py`. Existing membership and luminance
fixtures remain. Network encodings belong to `bace-wire`; complete stock-client
session qualification is a separate runtime gate.
